# 0.2 完整使用流程验收

目标仍是三个实用工具：Chrome 标签整理、飞书反馈分诊、GitHub 工具收藏分类。增强本地交互、配置、批处理、恢复和交付，不启动桌面预览，不发布到外部平台。

## 交付要求

1. **本地操作台**：无需记命令即可运行 GitHub / 飞书流程，明确的密钥会话设置、真实 / 演示状态、进度、取消、失败信息、历史和结果下载。只监听 127.0.0.1，不自动打开浏览器，凭据不落盘。
2. **Chrome**：分组预览搜索、全选 / 取消、手动调整分类、阈值与分组偏好、完整窗口分批分析、进度 / 取消 / 中断恢复、保留与撤销；异常和页面变化不导致静默丢失撤销记录。
3. **GitHub**：用户 Star / 指定仓库两种入口，分页与明确上限，增量缓存，搜索 / 分类 / 形态 / 语言筛选，人工纠正，Markdown / JSON / 独立 HTML 导出，Action 同步支持。
4. **飞书**：配置向导、字段检查、待处理记录筛选与视图、可审阅的计划，逐条确认 / 排除 / 修正，应用进度和部分失败回执，幂等恢复、冲突跳过及有变更检测的撤销。
5. **工程交付**：可重复构建与打包、无凭据离线完整演示、类型 / 单元 / 平台 / UI 端到端验证、更新后的安装与隐私文档。未运行的真实账号验证必须明确列出。

## 验证方法

模型契约与平台行为使用固定响应和故障注入验证；操作台使用独立无头浏览器验证完整用户操作；浏览器扩展用独立临时配置文件和无头浏览器验证，始终不加载用户现有浏览器配置、不弹出桌面窗口。界面截图仅在本地测试目录用于内部检查，不打开或展示给用户。

真实模型准确率、TypeSafe 账号权限、飞书租户授权不由离线测试替代。提供可选联调命令并如实保留验证状态。

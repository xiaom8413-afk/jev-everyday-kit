# 本地工作台

## 启动和连接

```bash
node dist/jev.mjs serve --port 4318 --data output/studio
```

仅绑定 `127.0.0.1`，不会自动打开浏览器。方便时访问程序打印的本机地址。不同端口可以运行独立工作台，但不要让两个服务共用同一数据目录。

工作台提供概览、GitHub 工具箱、飞书分诊、Chrome 安装指引和连接设置。无需密钥即可运行 GitHub、飞书的完整离线演示；示例内容是虚构占位，模型结果是固定样例，页面和导出文件均有标注。

连接设置中填入的凭据只保存在当前服务进程内存；保存后输入框清空，前端只收到“已配置”状态，不会收到原密钥。“已配置”表示已填写，不代表远程账号认证已通过。可主动清除会话凭据。运行任务时不能切换凭据，以避免前后身份不一致。

使用 `.env` 或环境变量提供的凭据同样只加载进内存。`.env` 文件本身由你保管，工作台不会修改它。

## 操作流程

### GitHub

1. 选用户名的 Star，或者粘贴每行一个仓库的清单。
2. 选择数量上限、分类阈值，需要重新推理时勾选忽略缓存。
3. 整理后按名称、简介、topics、备注搜索；按用途、形态、语言和归档状态筛选。
4. “调整分类”可保存人工类别、形态和备注。人工修正与模型判断有明确标记，下次同一来源的整理会保留。
5. 下载 Markdown、JSON 或可独立打开的离线 HTML。HTML 支持搜索和筛选，不加载外部资源。

### 飞书

1. 粘贴 `/base/` 表格地址，或填写 App Token、Table ID、可选 View ID。Wiki 链接需先找到对应 Base Token。
2. 填写输入列和四个输出列，使用“检查字段”；缺少输出列时可以查看具体列名后创建。
3. “生成分诊计划”只读取和分类，不回填。
4. 可只看待确认项、搜索反馈、调整类别 / 优先级，或取消选择不处理的记录。
5. 点击回填，审阅确认框中的条数和四个列名后执行。演示计划不能执行真实回填。
6. 查看成功、已处理、冲突、失败、未处理数量，下载回执。可继续失败 / 中断的回填，或检查变化后撤销本次成功写入。

已有回填回执的计划不能再修改，避免回执与实际内容脱节。修改输入后请生成新计划。开始撤销后，不会允许继续应用旧计划；如需再次分诊请生成新计划。

## 任务与恢复

同一平台同时只运行一个任务，GitHub 和飞书可以各运行一个。运行时显示阶段和进度，允许取消。

- GitHub 每完成一个批次就保存分类缓存。之后失败或取消时，下次可以复用已完成的判断。
- 飞书每完成一条回填或撤销就保存回执。取消会在安全的记录边界停止；已发出的写入会等待结果，避免把结果不明的操作误报为取消。
- 浏览器页面刷新不影响后台任务。任务状态和完成结果保存在本机历史中。
- 服务进程意外结束后，之前正在运行的任务显示“已中断”，不会悄悄自动重启或再次扣费。
- 网络异常无法确认写入时，回执会记录失败。重试同一计划会重新检查实际内容，避免重复写入。

## 保存位置与隐私

`--data` 指定目录中的 `jobs/` 保存任务、计划、结果和回执；`catalogs/` 保存 GitHub 目录与缓存。没有密钥。反馈预览及平台标识属于你的工作数据，会保存在本地。

需要清除所有工作记录时，先停止服务，再自行删除这个数据目录。不要把数据目录放进公开仓库或多人共享目录。工作台不自动上传历史，不部署网页，也不发群消息。

`Ctrl+C` 会请求取消活跃任务，等待在途操作保存回执，再关闭服务。
